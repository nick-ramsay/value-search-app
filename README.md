This is a [Next.js](https://nextjs.org) project bootstrapped with [`create-next-app`](https://nextjs.org/docs/app/api-reference/cli/create-next-app) and styled with Bootstrap.

## Getting Started

### MongoDB Setup

Set the following environment variables before running the app:

```bash
export MONGODB_URI="mongodb://localhost:27017"
export MONGODB_DB="value_search"
```

The home page reads from the `values` collection and renders up to 25 documents.

### Monthly balances (signed-in users)

The **Monthly balances** page (`/monthly-balances`) is protected the same way as **Portfolio**: unauthenticated visitors are redirected to `/login` (with a return URL). After you sign in, open it from the user menu in the navbar.

- **Collections:** `usermonthlybalancesheets` (`UserMonthlyBalanceSheet`) holds accounts and month rows, plus **`yearlyNetWorthAveragesMatchSheet`** (`Boolean`, default `false`): when **`true`**, stored yearly aggregates match the sheet; **`false`** means the sheet changed since yearly averages were last computed (any PATCH that can affect Net also sets this to **`false`**). **`currencyusdexchangerates`** (`CurrencyUsdExchangeRate`) stores **USD per one unit** of each tracked ISO currency (`usdPerUnit`, timestamps). An **AUD** row is created on first use of the FX helpers so the collection is never empty of that starter entry. **`usernetworthyearlyaverages`** (`UserNetWorthYearlyAverage`) stores one document per user per **calendar year** with **`averageNetUsd`** (mean of monthly **Net (USD)** for months in that year that have a full, computable total) and **`monthCount`**. Those averages are recomputed **only when needed**: **`GET /api/monthly-balances`** and **`GET /api/monthly-balances/yearly-averages`** call the sync function **only if** `yearlyNetWorthAveragesMatchSheet` is not **`true`** (missing/`false` means stale); after a successful sync the flag is set to **`true`**. PATCH handlers do **not** run sync—they only mark the sheet stale. Years with no valid monthly nets remove that year’s row for the user.
- **Yearly trend & projection** (`usernetworthprojections` / `UserNetWorthProjection`): one document per user, upserted whenever yearly averages are recomputed. Historical **`averageNetUsd`** values are **means of monthly balance-sheet Net snapshots** (wealth levels), not monthly income. When the first and last historical averages are both positive and span at least one year, **`simpleAnnualizedGrowthRate`** stores the **CAGR** between those endpoints (fraction, e.g. `0.04` ≈ 4% per year); otherwise growth is treated as **0%** for projection. For each of the next **30** calendar years (**current year + 1** through **+30**), **`projectedNetWorthUsd`** is **baseline net (latest month)** compounded annually: baseline × **(1 + CAGR)^t** (`t` = 1 for the first projected year). If there is no yearly data left, the projection document is removed. **`GET /api/monthly-balances/yearly-averages`** returns **`rows`**, **`trendAndProjection`** (or `null` if none), and still triggers sync when the sheet is stale.
- **Monte Carlo reference (Python worker):** `usernetworthmontecarlosimulations` (`UserNetWorthMonteCarloSimulation`) can be populated by the sibling **`value-search-pyworker`** script `projections/monte_carlo_net_worth.py` (or `projections/run_all_monthly_balance_projections.py`) for distribution-style 30-year net-worth scenarios (see that repo’s README). When **Year averages** or **Projections** is selected, the client also loads **`GET /api/monthly-balances/monte-carlo-simulation`**. If a document exists, the **Projections** bar chart uses the stored **median (p50) “most likely” net worth in USD per projected year** instead of the CAGR-compounded series from **`trendAndProjection`**. Re-run the worker after upgrading it so stored `methodVersion` and numbers stay in sync with the latest estimator.
- **Behavior:** Each account has an ISO 4217 **currency**; asset balances are stored as positive numbers and debt balances as negative numbers. **Net** is always shown in **USD**: each entered cell is multiplied by that account currency’s `usdPerUnit` and summed (debts stay negative). If a rate is missing for a currency used in a row, Net shows an em dash for that row. While the sheet is loading from the API, a spinner appears in the table area instead of the grid or empty-state copy. **Edit lock:** the header **Edit** / **Locked** toggle prevents editing balance cells (desktop table and mobile cards). **Locked** uses a red (`btn-danger`) button; **Edit** uses green (`btn-success`). **Locked is the default.** The value is stored in `localStorage` under **`value-search-mb-balance-cells-locked`** (`1` = locked, `0` = explicitly unlocked; missing key keeps the default locked). Locking while a cell is focused saves that cell (same as blur) then clears edit mode.
- **Exchange rates:** When a user **creates** an account, that account’s currency is **upserted** into `currencyusdexchangerates` if it was not already present. On **sign-in** (NextAuth `signIn` event) and whenever the monthly-balances API returns sheet data, the server ensures each non-USD currency on the user’s active accounts has a row; if the rate is **missing** or **older than 24 hours**, it **fetches** current USD-based rates from the public [Frankfurter API](https://www.frankfurter.app/) (`api.frankfurter.dev`, ECB data) and updates MongoDB. The GET/PATCH responses include a **`rates`** map (code → `usdPerUnit`) for the client Net calculation.
- **Layout:** The **Monthly Balances** title sits in its own compact **`liquid-glass-card`** at the top. When the sheet has finished loading, the main column shows empty-state copy when needed, then **`monthly-balances-chart-view-section`** with a **Charts** subheading and toggles for **Monthly sheet** / **Year averages** / **Projections**, then the chart for the selected view. Directly **below the charts**, a **`monthly-balances-toolbar`** (also **`monthly-balances-table-toolbar`**) glass panel holds **Cells** (Edit/Locked), **Data** (Export CSV, Upload from CSV, Columns), and **Add new account** / **Add new month** with the same expandable panels as before—**above the balance grid** (the grid section is omitted only when there are no months and no accounts yet). The last chosen view is stored in `localStorage` as **`value-search-mb-table-view`** (`sheet`, `yearly`, or `projections`). **Year averages** shows a **bar chart** of average monthly Net (USD) per calendar year above the balance grid (same SVG styling as the monthly Net chart; years chronological left to right, x-axis shows year and month-count line). **Projections** shows a **single** bar chart: **Monte Carlo median (p50) per year** when a stored simulation exists, otherwise **CAGR-compounded total Net by year** from **`trendAndProjection`**, with a **Year-by-year values** accordion under the chart that opens to a compact table of the same estimated amounts per year. The balance table stays visible for every view so you can keep editing while reviewing averages or projections. **Year averages** and **Projections** both trigger **`GET /api/monthly-balances/yearly-averages`** (`rows` + `trendAndProjection`; yearly rows come from `usernetworthyearlyaverages`); the same fetch loads **`GET /api/monthly-balances/monte-carlo-simulation`** for the projections chart when applicable. The client refetches when the sheet data changes while you stay on either view. While loading, only a spinner card appears under the title (toolbar is omitted until data is ready). In **Monthly sheet** view, when you have at least one account and at least one month row, a **Net (USD) by month** bar chart appears above the grid, using the same Net (USD) rules as the column, with months in **chronological** order (earliest on the left; the table lists months with the newest first). The x-axis shows a **short month** and **year** on two lines; if there are many months, the chart grows wider and **scrolls horizontally** so labels stay readable—hover a bar for the full month name and net amount. **`monthly-balances-table-viewport`** is a transparent, borderless scroll container (`width`/`max-width: 100%`, **`min-width: 0`**, **`max-height`**, no padding); the **`monthly-balances-table`** keeps **`width: max-content`** so wide grids scroll inside the viewport instead of widening the page. On desktop, the viewport **starts scrolled to the right** so **Net (USD)** and the right-hand account columns appear first (scroll left to reach the Month column).
- **Sticky columns:** The Month and Net columns stay fixed while you scroll horizontally (viewport width ≥ 768px). Their backgrounds use a solid base color under the glass tint so account cells do not appear to slide past the inner edges of those columns. Scrolling account headers/cells use opaque fills instead of frosted blur so content does not read through at the seams next to sticky columns. **`thead` corner cells use higher `z-index` (7 / 8) than **`tbody` sticky cells** (2 / 3) so when scrolling vertically, body Month/Net cells stay behind the entire header row—including the Month / Net (USD) labels—like the account headers.
- **Small screens:** Below the `md` breakpoint (narrow phones and small tablets), the sheet switches to a **card-per-month** layout: each month shows Net (USD) in the header and one row per account with currency, full-width tap targets for balance entry, and the same save/edit behavior as the desktop table. The wide spreadsheet table is not shown on small viewports to avoid horizontal scrolling.
- **CSV export:** On **Monthly Balances**, under **Data**, **Export CSV** downloads a pivot file: each row is a **`YYYY-MM`** month, the first column is **`Month`**, and each remaining column is the **signed total** (assets positive, debts negative) for all accounts that share the same **asset/debt kind**, **account type**, and **English ISO currency display name** (for example `Asset Checking (US Dollar)`). Amounts are **rounded to two decimals** like the rest of the sheet; months are **oldest first**; empty cells mean no balance was entered for that group in that month.
- **CSV upload wizard:** From **Monthly Balances**, use **Upload from CSV** to open `/monthly-balances/upload` (signed-in only). The file must be `.csv`. The first column is month labels as **MONTH-YEAR** in English (e.g. `August-2018` or `Aug-2018`). The first row’s remaining columns are **account names**; every data row must have exactly as many columns as the header. Balance cells must be empty or valid numbers (invalid text fails the upload). Each **YYYY-MM** month must appear at most once. Purely negative non-zero values in a column suggest **Debt**; purely positive **Asset**; mixed-sign columns are flagged. Amounts are rounded to **two decimal places** on import (client analysis and server save). After analysis, you can **edit account names** and must **choose** account type and currency (no defaults), adjust Asset/Debt, then **Save to Monthly Balances**. If the sheet **already has** accounts or month rows, a modal offers **add as additional data** (merge, same name rules as a normal import) or **overwrite** (with a second step: type `I am sure` and confirm) which purges the sheet and imports only the CSV. The client calls `PATCH /api/monthly-balances` with `op: "wizardImport"` and `sheetMode` `merge` or `replace`. Future months are still rejected; merge mode cannot use a name that matches an active or archived account.
- **Months vs accounts:** With no saved sheet, or no months and no accounts, the table is empty. You can add months before accounts (month-only rows, no balance columns). When you have at least one account but no month rows, the server adds the **current calendar month** as the first row automatically.
- **Adding months:** The UI supports a single month (`addMonth`) or an inclusive **From / Through** range (`addMonthRange`); months already stored are skipped so nothing is duplicated.
- **Deleting months:** With the sheet in **Edit** mode (not **Locked**), each month row has a delete control. A modal requires typing the **month label** exactly as shown in the row (e.g. English full month and year as displayed). The **`removeMonth`** PATCH op deletes that `monthRow`. If you remove every month while at least one active account remains, the server inserts the **current calendar month** again (same behavior as loading with accounts but no months).
- **Archiving accounts:** Removing an account from the table uses a confirmation modal and sets `archived: true` on that account (balances remain in MongoDB but are omitted from API responses until you **restore** via `restoreAccount`). Creating a new account with the **exact same name** as an archived one returns `409` with `code: "ARCHIVED_ACCOUNT_EXISTS"` and `archivedAccountId`; the UI offers **Restore archived account** instead of duplicating.
- **Editing accounts:** The account info modal lets you change name, asset/debt, account type, and currency. Unsaved changes show a **Save** button; saving uses the `updateAccount` PATCH op (same duplicate-name and archived-name rules as `addAccount`). Switching between asset and debt **re-signs** stored balances for that column so magnitudes stay the same.
- **Unvested RSU:** Under asset account types, **Unvested RSU** adds a **vesting date** (`YYYY-MM-DD`) stored on the account; it is required when this type is selected. When you choose this type while adding an account, a date field appears and defaults to **four years** from today (local calendar date). The CSV upload wizard applies the same default if you assign **Unvested RSU** without sending a date.
- **Real Estate auto-growth:** Under asset account types, **Real Estate** adds **Annual Growth (%)** (default `4`). The value is stored on the account as `annualGrowthPercent`. When you add new month rows (`addMonth` or `addMonthRange`), each Real Estate account with a prior-month value auto-fills the new month using monthly compounding: `newMonth = priorMonth * (1 + annualGrowthPercent / 1200)`, rounded to 2 decimals.
- **Exempt from Net Worth:** In **Account details**, you can check **Exempt from Net Worth** so that account’s balances are **not** included in each row’s **Net (USD)** total (balances still display normally). The flag is stored on the account (`exemptFromNetWorth`).
- **Column visibility:** Use **Columns** in the sheet header (or the **Hide this account column** toggle in **Account details**) to show or hide account columns. Hidden column ids are saved per user on the monthly-balance sheet (`hiddenColumnIds`) so your choices persist across logins. Hiding a column affects the grid only: **Net (USD)** still includes every active account except those marked **exempt from net worth** (same totals as the monthly Net chart and server-side yearly averages).

### MongoDB Atlas and "Server selection timed out"

If you see `MongoServerSelectionError: Server selection timed out after 30000 ms` on Vercel, the app cannot reach your MongoDB Atlas cluster. Vercel runs on dynamic IPs, so Atlas must allow connections from anywhere:

1. In [MongoDB Atlas](https://cloud.mongodb.com/) go to **Network Access**.
2. Click **Add IP Address**.
3. Choose **Allow Access from Anywhere** (adds `0.0.0.0/0`).
4. Confirm.

Use a strong database username and password; access is still protected by credentials. Ensure `MONGODB_URI` and any other required env vars are set in your Vercel project **Settings → Environment Variables**.
